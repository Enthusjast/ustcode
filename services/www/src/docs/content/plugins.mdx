title: "Plugins"
---

Add published packages, versioned packages, scoped packages, or local plugin directories to `ustcode.json(c)`.

## Configure

```jsonc title="ustcode.jsonc"
{
  "$schema": "https://ustcode.enthusjast.cc/config.json",
  "plugins": [
    "ustcode-acme-plugin",
    "ustcode-acme-plugin@1.2.0",
    "@acme/ustcode-plugin",
    "./plugins/local",
    "../shared/plugin.ts",
    "/absolute/path/plugin.ts",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/ustcode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Relative paths resolve from the config file containing the entry. Plugin arrays from applicable config files are applied
from lowest to highest precedence instead of replacing one another.

```text
~/.config/ustcode/ustcode.jsonc
./ustcode.jsonc
./.ustcode/ustcode.jsonc
```

## Discover

USTCode also loads direct `.ts` and `.js` files and immediate plugin package directories from every discovered
`.ustcode/plugins/` directory.

```text
.ustcode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/
```

Global plugins use the same discovery layout under the USTCode config directory.

```text
~/.config/ustcode/plugins/
```

A `plugins/` directory beside a project-root `ustcode.json(c)` is not discovered automatically; configure its files
explicitly or move it under `.ustcode/`.

```jsonc title="ustcode.jsonc"
{
  "plugins": ["./plugins/local"]
}
```

## Control

Plugin entries are processed in order. Prefix an ID or wildcard with `-` to disable it, use `*` for every plugin, and
use `.*` to match an ID prefix. A later ID re-enables a plugin.

```jsonc title="ustcode.jsonc"
{
  "plugins": ["*", "-ustcode.provider.*", "ustcode.provider.openai", "-acme.reviewer"]
}
```

The built-in `ustcode.config.policy` plugin ignores removals so that a repository
cannot switch off [policy](/policies) enforcement.

## Manage

Install, list, check, update, or remove global package plugins with the CLI.

```sh
ustcode plugin add ustcode-acme-plugin@1.2.0
ustcode plugin list
ustcode plugin list --builtin
ustcode plugin check
ustcode plugin update
ustcode plugin update ustcode-acme-plugin
ustcode plugin remove ustcode-acme-plugin@1.2.0
```

`plugin check` checks server and TUI-only package plugins for updates. `plugin update` updates every outdated package;
pass a configured package target to check or update only that package. Local plugins and exact package revisions are skipped.

Package installation accepts npm names with versions, tags, or ranges, plus npm-compatible Git package specifications.
Git repositories can use hosted shortcuts, HTTPS, or SSH, including private repositories available through your existing
Git credentials.

```sh
ustcode plugin add @acme/ustcode-plugin@latest
ustcode plugin add github:acme/ustcode-plugin
ustcode plugin add git+ssh://git@github.com/acme/ustcode-plugin.git#main
ustcode plugin add 'github:acme/plugins#main::path:packages/ustcode-plugin'
```

Branches, tags, complete commit hashes, and npm's `::path:` repository-subdirectory selectors are supported. Configure
local paths directly; tarball and npm alias targets are not accepted by `plugin add`.

## Reload

Changes under watched config directories reload automatically. Server startup loads cached package plugins immediately,
installs missing packages in the background, and checks unpinned npm and Git plugins for updates without changing the
installed package. Exact npm versions and full Git commit hashes stay pinned. Changes to unwatched local dependencies may
still require restarting USTCode.

```sh
touch .ustcode/plugins/concise/index.ts
ustcode service restart
```

## Terminal

CLI-only plugins are configured separately and remain active when connected to a remote server.

```json title="cli.json"
{
  "plugins": ["ustcode-acme-cli"]
}
```
